MediaGallery 1.8.0 Administrator Guide

MediaGallery is a media-management plugin for Geeklog. This guide is intended for site administrators and documents the maintained 1.8.0 behavior.

Requirements

MediaGallery 1.8.0 targets Geeklog 2.1.1 or newer, including Geeklog 2.2.2. The source keeps PHP 5.6-compatible syntax for legacy Geeklog 2.1.1 deployments while development also covers newer PHP versions.

Image uploads require a configured image-processing backend: GD, ImageMagick or NetPBM. If the selected backend is unavailable, MediaGallery reports the problem rather than continuing into an undefined image-processing call.

Albums and media

Albums can be nested and have their own title, description, owner, visibility, permissions, sorting, cover and display settings. The synthetic Root Album is the top of the tree and does not accept direct media uploads.

Media items can carry titles, descriptions, keywords, category information, ownership data and optional attached thumbnails. Administrators can edit, move, delete, rotate, watermark and reorder permitted media through the maintained interfaces.

Uploads and imports

Browser upload, Remote Media and FTP/import entry points use Geeklog security checks. MediaGallery rejects unsafe executable/server-side filenames and validates explicitly handled MIME/extension combinations.

  • Browser uploads preserve the options associated with each upload slot.
  • Remote Media accepts bounded public HTTP(S) sources and rejects localhost/private/reserved targets and redirects.
  • FTP imports are confined to the configured import area.
  • ZIP imports reject traversal paths, symbolic links and unsafe/excessive payloads.
  • Recursive CLI imports reject symbolic links and preserve nested directory-to-album mapping.

Batch processing

Long-running operations use MediaGallery batch sessions. The sensitive action that starts a batch keeps Geeklog's normal CSRF checks.

On Geeklog 2.1.1, continuation and cancellation are POST-only and use the server-generated MediaGallery session identifier plus session ownership validation. They deliberately do not require Geeklog 2.1.1's referer-bound one-time CSRF token on every internal continuation step, which avoids false “security token expired” failures.

Permissions, member albums and moderation

MediaGallery uses Geeklog's security model. Album access is revalidated server-side for maintained mutations; hiding controls in the interface is not treated as authorization.

Member albums allow eligible users to manage their own gallery area when enabled. Hidden or non-public albums are not exposed as public items through the 1.8 interoperability layer.

Moderated uploads are kept in the Geeklog/MediaGallery queue until approval. The 1.8 flow revalidates queued album/media relationships and administrator rights before promoting or rejecting queued content.

Playback and slideshow

Maintained playback no longer executes Flash, ActiveX or QuickTime browser plugins. Audio/video uses native HTML5 where practical, with safe download/fallback behavior for unsupported legacy formats such as FLV or SWF.

The maintained slideshow provides keyboard navigation, touch/swipe behavior, autoplay controls and reduced-motion consideration. Album and media pages remain the primary indexable content surfaces.

SEO and accessibility

  • semantic album/media headings and modern responsive markup;
  • canonical URLs for media and paginated albums;
  • meta descriptions derived from editorial album/media descriptions;
  • conservative JSON-LD for eligible local image/audio/video items;
  • improved form labels, keyboard behavior and escaping;
  • sharper album cards using local originals when available instead of scaling small square derivatives.

Persistent media storage

MediaGallery 1.8.0 stores persistent user media below Geeklog's configured image root, not inside the replaceable public plugin directory.

$_MG_CONF['path_mediaobjects'] = rtrim($_CONF['path_images'], '/\\') . '/mediagallery/';

A typical single-site location is public_html/images/mediagallery/. Shared-code multisite installations can provide site-specific path_images, images_url and path_data values to keep each site's media and temporary data isolated.

Upgrading from MediaGallery 1.7.x

Important: if the existing site still stores media under public_html/mediagallery/mediaobjects/, run the supplied pre-migration tool before uploading the 1.8.0 ZIP:

php tools/migrate-media-storage.php /path/to/geeklog

The tool copies and verifies the files into persistent storage and deliberately leaves the legacy source untouched.

Configuration

Administrator-editable values use Geeklog's Configuration API. MediaGallery 1.8.0 does not restore the historical manually edited plugin config.php. Runtime-derived plugin URLs, template paths and media storage paths are calculated from Geeklog configuration.

Fresh installs no longer expose obsolete Flash/FlowPlayer settings.

Interoperability

MediaGallery exposes content through Geeklog plugin APIs rather than requiring consumers to query mg_* tables directly.

The read-only album_list service is available through PLG_invokeService(). Media lifecycle events keep historical media IDs, while albums use namespaced IDs such as album:52.

Album/media changes can therefore be consumed generically by IndexNow, XML Sitemap, Hub and future connectors. MediaGallery does not call those plugins directly.

Troubleshooting

Images fail but other files upload

Check the configured image-processing backend. For GD, verify that the PHP GD extension is loaded. For ImageMagick or NetPBM, verify that the configured binaries are executable by PHP.

Batch operation reports an expired token on Geeklog 2.1.1

Use a current 1.8.0 build. The maintained batch continuation no longer depends on the legacy referer-bound token at each continuation step.

Member-album PHP block reports a missing helper

Use the current 1.8.0 block implementation. The member-album PHP block loads the shared MediaGallery helpers it needs explicitly.

Media disappear during a 1.7.x to 1.8.0 ZIP upgrade

Restore from backup if necessary. Do not retry the ZIP upgrade until the legacy media tree has been pre-migrated to persistent storage.

Portrait cards look soft or square

Current 1.8.0 cards prefer the local original as the visual source when available and use CSS cropping rather than enlarging old square derivatives. Confirm the deployed files are from the current branch and clear any theme/browser cache.
