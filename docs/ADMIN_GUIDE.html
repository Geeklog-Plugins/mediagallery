MediaGallery 1.8.0 — Administrator Guide

This guide is intended for site administrators who already have MediaGallery installed. It focuses on day-to-day configuration, album and media management, moderation, maintenance and Geeklog integration.

1. Quick start

The functions used most often are available from the MediaGallery album and administration menus. A typical workflow is:

  1. Create an album.
  2. Set its title, description, owner/group and permissions.
  3. Choose which features are enabled: comments, ratings, RSS, slideshow, downloads, member uploads, moderation and so on.
  4. Add media with the browser upload form, Remote Media or an import method.
  5. Use Manage Media to edit titles, descriptions, categories, keywords, order and album cover.
  6. Use the MediaGallery administration area for global configuration, member albums, batch sessions, categories, EXIF/IPTC, reports and maintenance.

The Root Album is the top of the gallery tree. Create real albums below it; direct media uploads to the synthetic Root Album are not allowed.

2. General configuration

MediaGallery administrator-editable settings are managed through Geeklog's Configuration API. The exact options visible depend on the installed build, but the main groups control gallery behavior, display, uploads, image processing, member albums and integration with Geeklog.

Gallery access and integration

Login required
When enabled, only authenticated Geeklog users can browse MediaGallery regardless of anonymous album permissions.
What's New integration
Controls whether recent MediaGallery content is included in Geeklog's What's New output. New-comment processing can be disabled separately where available if it becomes too resource intensive.
User profile integration
When enabled, MediaGallery can add gallery information such as recent uploads or owned albums to Geeklog user profiles.
Usage tracking
When enabled, MediaGallery records gallery activity for the usage report. This produces additional database data, so enable it only when the report is useful.

File and image behavior

Preserve original filename
Controls whether MediaGallery retains a recognizable version of the uploaded filename rather than using only its internal generated name.
Discard original images
If enabled, the original uploaded image can be removed after MediaGallery has created the display and thumbnail derivatives. This saves disk space but removes the highest-quality source.
Image quality and display sizes
JPG quality, display dimensions and thumbnail-related options affect generated derivatives. Changing a setting generally affects new processing; existing images may need a rebuild operation.
Image-processing backend
MediaGallery can use the Geeklog-configured GD, ImageMagick or NetPBM backend. Use the environment check if image processing unexpectedly fails.

Batch options

Large operations are split into small cycles. Batch settings control how much work is attempted per cycle and how long MediaGallery pauses between cycles. Conservative values are preferable on shared hosting.

3. Albums

Albums are the main containers in MediaGallery. They can contain media and sub-albums, and each album can have its own display, upload, moderation and permission policy.

Creating and editing an album

Use Create Album from a gallery/album options menu. To modify an existing album, open it and choose the edit action. Editing also allows an authorized administrator to change its parent and therefore move it within the album tree.

Album cover

MediaGallery can use a media item as the album cover. Use Manage Media to select a specific cover. Resetting the cover returns the album to its normal automatic cover behavior. Albums may also support an attached cover image depending on the edit form and theme.

Featured albums

Where the feature is enabled, an album can be marked as featured and associated with a Geeklog topic/location. MediaGallery still applies album access rules before displaying featured content.

Sorting albums

Album ordering can be adjusted manually or through the administrative static-sort tool. The batch/static sort functions are useful when a large subtree needs a consistent order.

Global album attribute editor

The global attribute editor applies selected album settings to many albums at once. Only attributes explicitly marked for update are changed. A starting album can be used to limit the update to one branch of the tree.

Global album permission editor

The global permission editor performs the same kind of bulk operation for ownership and permissions. Use it carefully: a broad permission change can expose or hide a large portion of the gallery at once.

Deleting albums

Album deletion is permanent when content is deleted rather than moved. Review child albums and media before confirming a destructive operation. The administrative Batch Delete Albums tool is intended for experienced administrators and should be used with a current backup.

4. Album permissions

MediaGallery uses Geeklog's owner/group/member/anonymous permission model at album level.

AudienceTypical rights
OwnerRead and edit/manage the album.
Geeklog groupRead and, if granted, edit/manage.
Logged-in membersNormally read access; member-upload capability is configured separately.
Anonymous visitorsRead access only when explicitly allowed.

Hidden albums

A hidden album is omitted from normal gallery browsing for users without management access. Hidden albums can still be useful as repositories for media referenced through Geeklog content integrations such as autotags. Users with sufficient write/admin access can still see and manage them.

Force child permissions

When editing permissions on a parent album, MediaGallery can propagate the permission set to descendants where the interface offers that option. Use this only when all child albums are intended to share the same policy.

5. Media items

MediaGallery supports images, audio, video and generic downloadable files. The exact processing depends on media type, configured image tools and album policy.

Image media

For supported images MediaGallery normally creates a display image and thumbnail and may retain the original. Maximum dimensions, conversion/original-file options and watermark settings can affect the result.

Audio and video

Maintained 1.8 playback uses native HTML5 audio/video where practical. Unsupported legacy formats such as FLV/SWF are not executed through Flash; they fall back to safe download/legacy handling. Attached thumbnails are useful for media that cannot generate a representative preview.

Metadata

Each media item can have a title, description, keywords, category, owner, capture/upload information and optional attached thumbnail. Some audio/image formats may provide metadata that MediaGallery can extract automatically.

6. Uploading and importing media

Browser upload

The browser upload form is the normal way to add a small number of files. Each upload slot keeps its own title/caption, description, keywords, category, attached thumbnail and processing options.

Browser uploads are still constrained by PHP/web-server upload limits. If a file fails before MediaGallery can process it, check upload_max_filesize, post_max_size and the server/PHP logs.

Remote Media

Remote Media is intended for supported public HTTP(S) resources. Current 1.8 security rejects localhost, private/reserved network targets, unsafe redirects and unbounded downloads. A local thumbnail may be attached when appropriate.

FTP import

FTP import is useful for large batches that have already been transferred to the server. Files must be placed inside the configured import area. MediaGallery confines imports to that directory and revalidates paths before processing.

Recursive imports can map subdirectories to sub-albums. This is convenient when a directory tree already represents the desired gallery hierarchy.

ZIP import

When ZIP import is enabled, MediaGallery can process archives containing multiple media files. Current 1.8 handling rejects path traversal, unsafe temporary paths, symlink members, excessive entry counts and excessive declared uncompressed payloads.

Command-line import

For server-side bulk work, the command-line importer can process files recursively. Current 1.8 handling rejects symbolic links and preserves the intended directory-to-subalbum relationship.

What happens after an upload?

Depending on the media type and album settings MediaGallery may:

  • validate the user's upload rights;
  • validate the media type and file-size limit;
  • validate filename and MIME information;
  • create thumbnail and display derivatives for images;
  • resize images that exceed album limits;
  • apply an automatic watermark;
  • extract selected metadata;
  • place user submissions into moderation;
  • notify moderators;
  • update RSS/search/integration state.

Manage Media is the central interface for editing and performing bulk actions within an album.

Detailed media edit

The detailed editor can expose fields such as title, description, keywords, category, capture time, owner, attached thumbnail and file replacement depending on media type and permissions. It also provides reset operations such as view/rating resets where supported.

Always save the form after replacing a file or attached thumbnail; choosing a local file alone does not update the media item.

Static media sorting

The administrative static-sort tool can reorder media across one album or an album subtree using properties such as capture time, upload time, title or original filename, depending on the available choices in the current build.

8. Moderation

Moderation allows registered users to submit media without publishing it immediately.

  1. Enable member uploads on the album.
  2. Enable moderation for that album.
  3. Select the Geeklog moderator group.
  4. Optionally enable moderator email notification.

Queued items remain pending until an authorized moderator approves or rejects them. Approval promotes the queued media into the active MediaGallery data/files. Rejection removes the queued item and associated queued files.

MediaGallery 1.8 revalidates the queued media/album relationship during moderation rather than trusting posted IDs.

9. Member Albums and quotas

Member Albums give selected site users their own gallery area. They can be created automatically, by self-enrollment or administratively, depending on configuration.

Main Member Album settings

  • enable/disable Member Albums;
  • choose the Member Album root;
  • set a default per-user quota;
  • choose whether new accounts receive an album automatically;
  • control whether members may create additional child albums;
  • define default file-size and image-dimension limits;
  • set default permissions and moderation policy;
  • decide what happens to member albums when a Geeklog account is removed.

Self-enrollment

When self-enrollment is enabled, the MediaGallery member-album block can offer eligible users a link to create their own member gallery. The 1.8 block explicitly loads the MediaGallery helpers it requires, including on Geeklog 2.1.1.

User list and quotas

The Member Album user list shows MediaGallery-specific member information such as active status, quota and quota usage. Use it to suspend a user's member-gallery administration or adjust an individual quota.

Batch create member albums

This administrative function is useful when Member Albums are enabled after the site already has users, or when albums are created only on request.

Purge empty member albums

The purge utility helps identify empty Member Albums and their owners so unused galleries can be cleaned up.

Reset member flags

The reset utility reconciles MediaGallery's internal member-gallery state with the actual albums. It is mainly a repair/maintenance tool rather than a routine operation.

Rebuild quotas

If quota accounting becomes inconsistent after file/database maintenance, use the quota rebuild function to recalculate usage.

10. Categories

MediaGallery categories provide an additional classification layer for media. They are especially useful in MediaGallery search.

Use Category Maintenance to add, edit or delete categories. Media items can then be assigned to a category through upload/edit/manage forms.

Categories complement albums rather than replace them: albums define hierarchy and permissions, while categories provide cross-album classification.

11. EXIF/IPTC administration

Supported image files may contain camera and editorial metadata. MediaGallery can display selected EXIF/IPTC fields when album EXIF support is enabled.

The EXIF/IPTC administration screen determines which recognized metadata fields are eligible for display. Actual values depend on what is embedded in each image.

If privacy is important, review the fields you expose. Camera metadata can sometimes include timestamps, device details and location-related information.

12. RSS and podcasts

MediaGallery can provide overall and per-album feeds where those features are enabled.

Album RSS

Enable RSS in the album attributes when visitors should be able to subscribe to changes in that album. Sub-albums may be included depending on album options.

Podcast feeds

Podcast mode affects feed metadata for suitable audio/video content. Playback presentation itself is handled separately by the current HTML5 templates.

Rebuild feeds

The administration menu provides RSS rebuild operations. Normally feeds are updated as content changes, but a rebuild is useful after bulk metadata edits or when feed files/state need to be regenerated.

Before enabling a feed for restricted content, verify that the generated feed behavior matches the privacy expectations of the site.

13. Watermarking

MediaGallery can apply watermark images to eligible image media automatically during upload or manually through media management.

  • Select/upload a watermark image.
  • Configure its position and opacity where those options are exposed.
  • Enable automatic watermarking on the album if desired.
  • Use the Manage Media batch action for selective watermarking.

Watermarking changes image files. Keep originals/backups if you may need an unwatermarked source later.

14. Batch processing and maintenance

MediaGallery's batch system breaks expensive operations into smaller cycles to avoid long-running requests and excessive resource use.

Batch sessions

The administrator menu exposes paused/active batch-session management. On Geeklog 2.1.1, internal continuation is protected by POST plus the server-generated MediaGallery session identifier and ownership validation, avoiding false failures caused by Geeklog 2.1.1's referer-bound one-time token.

Rebuild thumbnails

Use this after changing thumbnail-related processing or when derivative files need to be recreated. A per-album rebuild may also be available from album administration.

Resize display images

Use this when display-image dimensions have changed and existing derivatives need to be regenerated.

Discard originals

This maintenance operation removes retained original images when the corresponding MediaGallery policy is enabled. This is destructive; do not run it unless you are certain the originals are no longer required.

Rebuild quotas

Recalculates Member Album disk usage.

Static sort albums / media

Applies a consistent sorting rule across selected albums or media sets.

Batch delete albums

Permanently deletes multiple selected albums and their content. Use with exceptional care.

15. Reports and environment checks

Usage report

When usage tracking is enabled, the report shows recorded MediaGallery activity. Disable usage tracking if the report is not needed and database growth is a concern.

Environment check

The environment check is the first administrative tool to use when uploads or image operations fail. It can help identify unavailable GD/ImageMagick/NetPBM support and other host-environment problems.

Geeklog logs

For unexplained failures inspect Geeklog's error.log and, when appropriate, the web server/PHP error log. MediaGallery errors are generally more actionable there than in a blank/partial browser response.

16. Geeklog integration

Comments

MediaGallery uses Geeklog's comment system when comments are enabled for an album. Geeklog comment protections and moderation behavior therefore apply.

Search

MediaGallery integrates with Geeklog search and also has gallery-oriented searching/filtering. Good titles, descriptions, keywords and categories improve discoverability.

What's New

Recent media and, depending on configuration, comments can appear in Geeklog's What's New output.

Featured albums

Featured albums can be surfaced in Geeklog pages/topics according to their configuration and permissions.

Random Image Block

The MediaGallery random-media PHP block can display an image selected from eligible albums. Enable/configure the block through Geeklog's Blocks administration. Albums can individually opt in/out of random-media selection.

User profiles

When MediaGallery profile integration is enabled, relevant MediaGallery information can be added to Geeklog user profiles.

17. Autotags

MediaGallery supports Geeklog autotags so albums and media can be embedded in stories, static pages and other Geeklog content that processes autotags. Autotags honor MediaGallery access rules.

Finding IDs

The album ID is the aid value in an album URL and may also be shown to administrators in MediaGallery. Media IDs are visible in the media detail/administration interfaces where enabled.

Common autotags

AutotagPurpose
[album:ID ...]Display/link an album cover.
[media:ID ...]General-purpose media thumbnail/display integration.
[img:ID ...]Render an image-oriented media reference.
[slideshow:ID ...]Embed a slideshow for an album/media set.
[fslideshow:ID ...]Legacy slideshow entry point retained for compatibility; current rendering is routed to maintained slideshow behavior rather than Flash.
[video:ID ...]Embed supported video media using maintained playback behavior.
[audio:ID ...]Embed supported audio media.
[download:ID ...]Provide a download link to a media item where access allows it.
[mlink:ID ...]Provide a text link to a media item.

Common optional parameters historically include width, height, alignment and caption text. Exact behavior varies by autotag and maintained template. Use the simplest form first and add presentation parameters only when needed.

Permissions and hidden albums

Autotags are useful for hidden albums used as editorial media repositories. The embedded output still follows MediaGallery permission checks; hiding an album from navigation is not a substitute for access control.

18. Themes and appearance

MediaGallery's public rendering is template-driven and 1.8 includes responsive modernization of the maintained album/media/search views.

Album themes can alter presentation for specific albums. When maintaining custom themes, copy/override only the files that need customization where the current theme structure permits it; minimizing overrides makes future upgrades easier.

After upgrading MediaGallery, review custom album themes against the maintained 1.8 templates because older overrides may retain obsolete markup or playback assumptions.

19. Troubleshooting

Image upload fails but a ZIP/PDF or generic file works

Image uploads require an operational image-processing backend. Check the MediaGallery environment page and verify GD is loaded or the configured ImageMagick/NetPBM binaries are executable.

Large browser upload fails before MediaGallery reports an error

Check PHP/web-server limits such as upload_max_filesize, post_max_size, memory limits and request timeouts.

Thumbnails/display images are not created

Check the configured image backend, writable MediaGallery storage directories and Geeklog/PHP error logs. Rebuild thumbnails only after the underlying processing problem has been fixed.

Batch operation reports an expired security token on Geeklog 2.1.1

Use a current 1.8.0 build. Current batch continuation no longer depends on Geeklog 2.1.1's referer-bound one-time token for each continuation request.

Member Album block reports a missing helper/function

Use the current 1.8.0 block implementation. The member-enrollment block explicitly loads the shared MediaGallery helper file it requires.

Portrait thumbnails look soft or square

Current 1.8 album cards prefer the local original as the visual source when available and use CSS cropping rather than enlarging old square thumbnail derivatives. Clear browser/theme caches after updating templates/CSS.

Moderated item cannot be approved

Confirm that the queued media still belongs to a valid target album and that the current account has the relevant MediaGallery administration/moderation rights. Review Geeklog's error log for rejected relationship or permission checks.

RSS output is stale

Use the MediaGallery RSS rebuild actions after bulk metadata/content changes if normal incremental updates did not refresh the expected feed.

General diagnostic procedure

  1. Reproduce the issue once.
  2. Check Geeklog's error.log.
  3. Check the web server/PHP error log.
  4. Use MediaGallery's environment check for backend/path problems.
  5. Verify album permissions and the exact account performing the action.
  6. For a batch action, check the MediaGallery batch-session state.

Scope of this guide: administrator usage after installation. Developer architecture, release planning, upgrade migration and interoperability contracts are documented separately in the repository.
