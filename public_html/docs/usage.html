MediaGallery 1.8.0 User Guide

MediaGallery is a media-management plugin for Geeklog. Version 1.8.0 modernizes the historical 1.7.x codebase while preserving albums, media, permissions, search, RSS, member albums and Geeklog integration.

Development status: MediaGallery 1.8.0 is still under release-candidate validation. Test upgrades on a staging or local copy and keep complete database and media backups.

1. Requirements

MediaGallery 1.8.0 targets Geeklog 2.1.1 or newer, including Geeklog 2.2.2. The source remains compatible with PHP 5.6 syntax for legacy Geeklog 2.1.1 deployments and is also developed against newer PHP versions.

Image uploads require a working image-processing backend because MediaGallery creates thumbnails and display images. Supported configured backends include GD, ImageMagick and NetPBM. Non-image files such as some document/archive types can be handled without image conversion.

2. Core concepts

Albums

Albums organize media and can be nested. Each album has its own title, description, owner, visibility, permissions, display options, sort rules, cover and optional moderation settings.

Media items

A media item is an image, audio/video file, supported document/archive or remote media entry. Media metadata can include a title, description, keywords, owner, category, capture/upload information and optional attached thumbnail.

Root Album

The Root Album is the top of the gallery tree. Create normal albums below it. Direct media upload to the Root Album is intentionally prevented in 1.8.0.

3. Getting started

  1. Open MediaGallery from your Geeklog site.
  2. Create an album below the Root Album or another album you can manage.
  3. Set the album title, description, permissions and display options.
  4. Upload one or more media items.
  5. Review the generated thumbnails, media detail pages and album page.
  6. Adjust the cover, order, metadata or permissions as required.

Administrators should first verify the configured image-processing backend and the MediaGallery storage directories before importing large media collections.

4. Albums

Album pages are the main browsing surface in MediaGallery. Version 1.8.0 uses responsive cards and preserves portrait and landscape proportions without forcing portrait originals through square thumbnail derivatives when the original local image can be used safely.

Create or edit an album

Users with sufficient rights can create and edit albums. Common options include title, description, parent album, owner/group, anonymous/member permissions, display rows/columns, thumbnail size, comments, ratings, RSS, sorting, slideshow, downloads and member uploads.

Moving an album

Changing an album parent updates the gallery hierarchy. Check inherited permissions after moving an album, especially when the old and new parent albums use different security rules.

Deleting an album

Deletion can remove content or move content to another permitted target album, depending on the selected operation. MediaGallery revalidates access before performing destructive operations.

5. Media items

Each media item can have its own public detail page. The maintained 1.8.0 templates emphasize the media itself, navigation, essential metadata, comments/ratings where enabled, and responsive display.

Titles and descriptions

Use descriptive titles and useful descriptions. Album and media descriptions are also used where appropriate for search-engine meta descriptions.

Keywords and categories

Keywords and MediaGallery categories can help organize and discover items. They are supplementary metadata; they do not replace a clear album hierarchy and meaningful titles.

Attached thumbnails

For media that cannot generate a representative image automatically, an attached thumbnail can be used. This is especially useful for video and other non-image media.

6. Uploading and importing

MediaGallery 1.8.0 hardens all maintained upload/import paths. Browser uploads, remote media and FTP/import actions validate permissions and request integrity before writing content.

Browser uploads

Browser upload supports multiple slots and keeps each slot's title, description, keywords, category, attached thumbnail and conversion/original-file options associated with the correct file.

Remote media

Remote fetching is limited to public HTTP(S) targets. Localhost, private/reserved network addresses and unsafe redirects are rejected. Downloads are bounded rather than accepted without limits.

FTP and ZIP imports

FTP paths are confined to the configured import area. ZIP processing rejects path traversal, symbolic links and unsafe/excessive archive payloads. Recursive command-line imports also reject symbolic links.

Filename and MIME validation

Executable/server-side filename patterns are rejected. MediaGallery prefers content-derived MIME information when available and checks coherence for formats it explicitly handles.

7. Managing media

The media manager can update titles, descriptions, keywords, category, display order and album cover. Batch actions can move, delete, rotate, watermark or otherwise process permitted items depending on media type and configuration.

Batch sessions

Long-running batch operations use a MediaGallery batch session. On Geeklog 2.1.1 the continuation request is protected by POST plus an unpredictable server-generated session identifier and ownership validation, rather than depending on Geeklog's legacy referer-bound one-time token for every internal continuation step.

The initial sensitive action still uses the appropriate Geeklog security checks before a batch is created.

Moving media

MediaGallery checks both the source and destination album before moving content. Moving a media item updates both album listings and the media's integration events.

8. Permissions and member albums

MediaGallery uses Geeklog's security model. Albums have owner, group, member and anonymous permissions. Direct access is rechecked server-side; hiding a link in the user interface is not treated as authorization.

Member albums

When enabled, member albums allow eligible users to create or enroll in their own gallery area. The member-album block loads the MediaGallery helpers it needs when invoked so it remains compatible with Geeklog 2.1.1 plugin loading.

Private and hidden albums

Albums that are hidden or not readable by anonymous users are not exposed as public items through the 1.8.0 interoperability layer.

9. Moderation

Albums can require moderation for member uploads. The 1.8.0 path revalidates queued album/media relationships, administrator/moderator rights and request tokens before approval or rejection.

Approved items are promoted into the active MediaGallery tables and files; rejected items are removed from the moderation queue and associated temporary/queued files are cleaned up.

10. Playback and slideshow

MediaGallery 1.8.0 no longer relies on active Flash, ActiveX or QuickTime browser plugins. Maintained playback uses native HTML5 audio/video where practical.

Media1.8.0 behavior
JPEG/PNG/GIF and other supported imagesResponsive image display and thumbnails.
MP3 and compatible audioHTML5 audio when supported by the browser.
MP4/MOV and compatible videoHTML5 video when browser/codec support is available.
Legacy FLV/SWFNo Flash execution; safe download/fallback behavior.
Other unsupported playback formatsDownload or fallback rather than obsolete browser plugins.

Slideshow

The maintained slideshow is an immersive native viewer with keyboard navigation, touch/swipe behavior, autoplay controls and reduced-motion consideration. Album and media pages remain the primary indexable content surfaces.

11. Search, RSS and discovery

MediaGallery integrates with Geeklog search and can generate gallery/album RSS feeds when enabled. Album and media changes continue to update the relevant MediaGallery feed paths.

Use album descriptions and media metadata to improve both human browsing and search results.

12. SEO and accessibility

MediaGallery 1.8.0 modernizes its public markup rather than adding SEO-only duplicate pages.

  • semantic album and media headings;
  • canonical URLs for individual media and paginated album views;
  • page-number title handling for album pagination;
  • meta descriptions based on existing editorial descriptions;
  • responsive image/media layouts;
  • more consistent labels and keyboard-accessible controls;
  • conservative JSON-LD for eligible local image/audio/video media.

Remote or embedded media are not given structured data when MediaGallery does not own enough reliable content, thumbnail or publication metadata.

13. Media storage

MediaGallery 1.8.0 treats uploaded media as persistent user data. Runtime media files are stored below Geeklog's configured image root, not inside the replaceable public plugin directory.

$_MG_CONF['path_mediaobjects'] = rtrim($_CONF['path_images'], '/\\') . '/mediagallery/';

A typical single-site path is:

public_html/images/mediagallery/

Shared-code multisite installations can provide a site-specific path_images, images_url and path_data so each site gets isolated public media and private temporary storage.

Upgrading from 1.7.x

Important: before uploading the 1.8.0 ZIP over a 1.7.x installation that still stores media under public_html/mediagallery/mediaobjects/, run the supplied pre-migration tool. Geeklog's plugin ZIP installer can replace the old public plugin directory before MediaGallery upgrade code runs.

php tools/migrate-media-storage.php /path/to/geeklog

The tool copies and verifies media into persistent storage and deliberately leaves the legacy source untouched.

14. Configuration

MediaGallery uses Geeklog's Configuration API for administrator-editable settings. Version 1.8.0 does not restore the historical manually edited MediaGallery config.php.

Runtime-derived values such as plugin URLs, template paths and media-storage paths are calculated from Geeklog configuration instead of being stored as arbitrary administrator values.

Fresh installations no longer expose obsolete Flash/FlowPlayer configuration controls. Upgraded sites may temporarily retain harmless legacy database rows while cleanup compatibility is validated.

15. Interoperability

MediaGallery 1.8.0 exposes content through Geeklog's plugin APIs so other plugins do not need direct access to MediaGallery database tables.

Album discovery service

The read-only album_list service can return a permission-filtered album tree through PLG_invokeService().

Lifecycle events

Media saves/deletes continue to use their historical media ID. Albums use a namespaced identifier:

album:52

Creation, editing, movement and deletion emit Geeklog lifecycle events. Changes to media also announce affected album pages. Consumers such as IndexNow, XML Sitemap, Hub or future connectors can resolve public URLs through the standard MediaGallery item-info contract.

Repeated album notifications are deduplicated within the same request.

16. Troubleshooting

Image upload fails but ZIP/PDF works

Verify that the configured image-processing backend is actually available. For GD, confirm the PHP GD extension is loaded. For ImageMagick/NetPBM, confirm the configured binaries are executable by PHP.

Batch reports an expired security token on Geeklog 2.1.1

Use a current 1.8.0 build. Batch continuation was adapted for Geeklog 2.1.1 so it no longer depends on a referer-bound one-time token at every continuation step.

The member-album PHP block says its function is missing or helpers are undefined

Use the current 1.8.0 bootstrap and legacy block implementation. The block entry point is loaded by Geeklog and the member-album block loads its MediaGallery common helpers explicitly.

Media disappeared after a plugin ZIP update

Do not perform a 1.7.x to 1.8.0 ZIP upgrade before the media pre-migration. Restore from backup if necessary and run the migration tool before retrying the plugin update.

Portrait thumbnails look square or soft

Current 1.8.0 album cards prefer the local original as the source for the card layers where available, using CSS crop/contain behavior instead of enlarging a small square derivative.
